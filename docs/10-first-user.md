# 最初の研究者で確かめること

alpha を最初の研究者に渡して、何が成り立てば前に進めるか。Node 版 v0.1 の設計（`docs/v0.1/08-design.md`）の §1 目的・§7 AI が質問する条件・§9 シナリオ・§12 成功条件を、alpha の形に直して移した。画面は [08-screens.md](08-screens.md)、流れは [09-usecases.md](09-usecases.md)、データの形は [05-data-model.md](05-data-model.md) §9。

## 1. 目的

研究者が rescicle の会話欄で研究について自然に話し、必要なら研究フォルダのファイルを示すだけで、問い・仮説・代替仮説・予測（判定式つき）・測定・データが AI によって提案され、研究者がマップで確かめて確定・却下できる。

> **研究について話すと、研究の構造が見える。そして AI もその構造を使って一緒に科学的に考えられる。**

この一点を成り立たせる。`PRODUCT_SCOPE.md` の仮説（10〜30 分の会話で、問い / 仮説 / 予測 / 測定 / データが以前より明確に見える）と同じことを言っている。

### 最初の Wow

インストールして 15 分。研究者が「いま、何を調べていますか」に「NV⁻ の T2* は窒素濃度で決まっていると思っている」と書くと、

```text
問い   HPHT ダイヤモンド中の NV⁻ アンサンブルの T2* は何で決まるか

仮説  研究者  提案中  置換型窒素の濃度に反比例する（窒素スピン浴）
 └ 予測  AI提案  判定: spearman(n_N, T2star) < 0
     └ 測定  N 濃度の異なる 3 試料で Ramsey
         └ データ  ramsey_S1.csv / ramsey_S2.csv / ramsey_S3.csv
仮説  AI提案  提案中  13C 核スピン浴で決まる
仮説  AI提案  提案中  電子線照射で生じた空孔関連欠陥が T2* を短くしている

補足（測定）: MW 離調が記録にない
```

がマップに現れる。**ここは Paywall の外**（D-13）。

## 2. AI が質問する条件

AI は何でも聞かない。聞くのは次のときだけ。

* A. 重要なつながりの確信が低い
* B. 仮説を見分けるのに要る
* C. 研究マップの理解が大きく変わる
* D. 誤って研究オブジェクトを作る可能性が高い
* E. 予測の判定に、誰も決めていない数（有意水準・効果量・試料数）が要る。AI は自分で決めずに、どの数が足りないかを言って聞く（`agent_instructions.md`、D-116）
* F. 実施済みの測定にデータが結ばれていない。どのファイルかを 1 回だけ、会話がその近くに来たときに聞く

「全部埋めよう」としない。分からないことは埋めずに、そのオブジェクトの補足（`note`）に書く（D-115）。オブジェクトにするか迷うものは作らず、返事の中で答える。

## 3. 一連のシナリオ

題材はダイヤモンド NV センタのスピンコヒーレンス（Node 版 D-99 と同じ**架空**の台本）。alpha の操作名は `response_schema.json` の `op` で書く。

1. 研究者が最初の画面に「12C 濃縮の HPHT ダイヤモンドで NV⁻ アンサンブルの T2* を測ってる。窒素濃度で決まってるんじゃないかと思ってる」と書いて **はじめる**。研究名は 1 行目の 30 字。研究フォルダはまだ無い（UC-1）。
   AI: `create_object(question, origin=researcher)` → 問い、`create_object(hypothesis, origin=researcher)` → 仮説 H「T2* は置換型窒素の濃度に反比例し、窒素電子スピン浴が主な位相緩和源」、`create_relation(H addresses 問い)`。すべて提案中。
2. AI「窒素浴なら [N] を半分にすると T2* は約 2 倍です。どう比べますか」。研究者「[N] が 1.3 / 0.6 / 2.8 ppm の板が 3 枚ある。Ramsey で測る」。
   AI: `create_object(prediction, origin=agent, criterion="spearman(n_N, T2star) < 0", criterion_note="3 試料。n_N は EPR の [Ns⁰]、T2star は Ramsey のフィット値", symbols=[n_N, T2star])`、`create_relation(H predicts 予測)`、`create_object(measurement, origin=researcher)`、`create_relation(予測 tested_by 測定)`。予測の論理は AI が導いたので origin=agent。
3. AI「他にも説明できます。13C 核スピン浴、電子線照射の空孔関連欠陥。候補として置きますか」。研究者「置いてみて」。
   AI: 仮説 2 つを origin=agent で作り、それぞれ `addresses` 問い。
4. 研究者がマップのカードを開き、問い・H・予測・測定を **確定**、13C の仮説を **却下**（3 分間は通知から戻せる。過ぎると消える。D-110）。
5. 研究者がデータ・ファイル画面で研究フォルダ `data/nv_t2star` を選ぶ。AI にはファイル名・サイズ・更新日時だけが渡る。
6. 研究者「S1〜S3 の Ramsey を見て」。AI が `read_files: [ramsey_S1.csv, …]` を返し、rescicle が先頭 4KB を読んで次のターンに渡す。読んだファイルに「読み込み済み」が付く（UC-3）。
7. AI: `register_asset` × 3、`create_relation(測定 produces データ)` × 3、`set_performed(測定, true)`。研究者は **実施した** の表示とデータのつながりを確かめる。
8. AI「M の MW 離調が記録にありません」。研究者「あとで調べる」。AI: `set_note(測定, "MW 離調 δ と π/2 パルス長が未記録")`。
9. AI「空孔の仮説と窒素の仮説を見分けるには、同じ [N] で照射量だけ変えた 2 枚を比べます。窒素浴なら T2* は変わらず、空孔なら短くなります」。予測を仮説ごとに 1 つずつ作る（判定式はそれぞれ `T2star_high - T2star_low = 0` と `T2star_high < T2star_low`、許容幅は研究者に聞く）。同じ測定に 2 つの予測が `tested_by` で入る — alpha で見分ける実験を表す形（protocol は無い。D-117）。

alpha でこの台本に**無い**もの: 観測と結果、`supports` / `contradicts`（予測が当たったかは本文と補足で書くしかない）、ラベル（H1 / P2）、履歴画面。

## 4. 成功条件

最初の研究者が rescicle を使って、

1. 自分の研究構造が以前より明確になった
2. 自分では明示していなかった代替仮説を AI が出した
3. AI が判定式を持つ、使える予測を提案した
4. 実際のデータが測定に（`produces`）、測定が予測に（`tested_by`）結び付いた
5. 「次に何を測ると情報量が大きいか」という議論ができた
6. AI が研究者の判断なしに確定したものが残っていない
7. フォーム入力より対話の方が楽だった
8. 研究マップをまた見たいと思った

### パイロット（`Pilot`）の判定方法

* 参加者: 実験系の研究者 3〜5 名。rescicle の開発者は含めない
* 課題: 各自の進行中の研究について 15 分会話し、研究フォルダのファイルを 1 つ以上データにする。インストールと Claude Code の用意（setup）は別に測る
* 事前に定める閾値:
  * 1: セッション前後で「自分の研究構造がどの程度明確か」を 5 段階で聞き、差分が +1 以上の参加者が過半数
  * 2: origin=agent の仮説の提案数・確定数と、確定したものの有用性評価（5 段階で 4 以上）が過半数
  * 3: origin=agent の予測の提案数・確定数と、判定式の実行可能性評価が過半数
  * 4: 確定した `produces` と `tested_by` がそれぞれ 1 件以上ある参加者が過半数
  * 5: 1 つの測定に 2 つ以上の仮説の予測が `tested_by` で結ばれ、確定しているものが 1 つ以上あり、有用性評価が過半数
  * 6: 全参加者の DB で、`events` の actor=`agent` の `object_confirmed` / `relation_confirmed` が 0 件（必須）。`researcher-via-agent` は研究者がそのターンで言ったものなので、会話の記録と突き合わせる
  * 7・8: 終了後の 5 段階アンケートで 4 以上が過半数
  * あわせてオンボーディング時間、確定・却下の操作数、読まれたファイル数（`file_read`）、離脱点を記録する
* 比較対象: 同じ研究者に同じ 15 分でフォーム入力式のテンプレート（問い / 仮説 / 予測の表）を埋めてもらい、7 の質問で比べる。フォーム先行と rescicle 先行を参加者で交互にする
* パイロットのデータは非機密のものに限る（U-02 が閉じるまで、会話と読まれたファイルの抜粋は Anthropic に渡る）

6 を満たした上で、残り 7 項目のうち 4 項目以上が閾値を超えれば成功。

これは 15 分の Wow 試験で、継続利用は 4 週間のデザインパートナー試用で別に測る（[04-business.md §2](04-business.md)）。
