# 画面一覧

v0.0.8 時点。`src/renderer/app.js` の `render()` / `contentHtml()` から起こしています。

**URLもルーターもありません。** 表示される画面は `state.workspace` の有無と
`state.currentScreen` の2つだけで決まります。

```
起動
 │
 ├─ プロジェクトが無い ──▶ ❶ オンボーディング
 │
 └─ プロジェクトがある ──▶ ❷ ワークスペース（以降ずっとこの1画面）
```

## ❶ オンボーディング

```
rescicle

いま、何を調べていますか
  そのまま書いてください。話すうちに、問い・仮説・予測・測定が
  「もの」として現れます。

  ┌──────────────────────────┐
  │ （自由入力）               │
  └──────────────────────────┘

  書き出しに迷ったら
   ( 最近うまくいっていない実験について話したい )
   ( 次にやる測定を決めたい ) ( 頭の中にある仮説を書き出したい )

                                        [ はじめる ]
```

- 書き出しの候補は押すと本文に入るだけで、送信しません
- **[はじめる] がプロジェクト作成と最初の発言の送信を兼ねます。** 着地するのは
  空のマップではなく、応答が走っている画面です
- **研究フォルダはここでは聞きません。** 会話に要らないので、データを登録したく
  なったときに ❹ で選びます

## ❷ ワークスペース

```
┌ トップバー ─────────────────────────────────────────┐
│ rescicle  [研究名]                 研究フォルダのパス      [設定] │
│            ↑クリックで改名          ↑ただの文字。操作は❹と❼    │
├──────────┬────────────────────────┬────────────┤
│ サイドバー  │ 中央カラム（❸〜❻のどれか1つ）│ 会話           │
│            │                          │                │
│ 検索欄      │ ┌ 通知（0〜3個）────┐  │ 会話 [Claude Code] │
│ (Ctrl+F)   │ │ 研究フォルダ変更の結果 │  │ 対象: ◯◯ / 研究全体│
│            │ │ Claude Code追加の案内 │  │                │
│ マップ      │ │ 却下の取り消し（3分）  │  │ メッセージ列     │
│ 問い     n │ └──────────────┘  │                │
│ 仮説     n │                          │ 入力欄 (Ctrl+K)  │
│ 予測     n │ ▼                        │ [送信]           │
│ 測定     n │                          │                │
│ データ・    │                          │                │
│  ファイル   │                          │                │
└──────────┴────────────────────────┴────────────┘
                                                 [設定] ▶ ❼
```

会話は常に右にあり、どの画面でも消えません。**「戻る」はありません** — 画面遷移が
無いので、戻る先がないためです。

中央カラムと会話の境目はドラッグで動かせます。幅は `--chat`（`:root` のCSS変数）
に書かれ、`localStorage` に残ります。ドラッグ中は再描画しません — 描き直すと
入力中の文字が巻き込まれるためです。最小300px、中央カラムの最小幅までが上限。

中央カラムの幅は画面によって変わります。カードと文章の画面は 820px、マップと
データ・ファイルは 1020px（マップの5列が 952px で収まる幅）。

## ❸ マップ（既定）

```
研究名
問い → 仮説 → 予測 → 測定 → データ のつながりです。右側のAIと話すと、
ここが育っていきます。

[ SVGの図。5列すべてが常に描かれる。空の列は見出しだけ薄く残る ]

実線 = 確定   破線 = 提案中（AI提案）   薄い線 = 参考（鎖ではない）
─────────────────────────────────────────
ノードを選ぶと下端に詳細パネル（sticky・影つき・中央カラムいっぱい）
  [これについて話す] [実施した] │ [確定] [却下]
   ↑ 押しても取り返しがつく      ↑ 判断。塗りつぶしは確定だけ、却下は赤
  └ Asset は [これについて話す] のみ
─────────────────────────────────────────
研究フォルダ未選択のときだけ、最下部に ❹ への導線
```

**空の列も残ります。** 中身のある列だけを詰めて描いていたときは、問いとデータ
しかない研究でその2つが隣り合い、鎖がそこで繋がっているように見えました。実際は
4つ離れています。空白そのものが「ここに仮説・予測・測定が入る」と言っています。

**参照する・関連するは薄く描きます。** この2つは型を選ばないので、仮説と測定の
ように鎖の線が来る位置に来ます。同じ見た目だったころは、作られていない予測を
またいで鎖が通っているように見えていました。

詳細パネルに**記録の管理は出しません**。マップは形を見る場所であって、帳簿を
置く場所ではないからです。Asset の「登録を取り消す」は ❹ にあります。

## ❹ データ・ファイル

```
データ・ファイル

データ                n件  │  フォルダ内のファイル      n件  [再スキャン]
 [カード]                   │   C:¥…¥research  別のフォルダに変更
 [カード]                   │  ▾ このフォルダの直下        5件
                           │      run3.csv    3 KB [データとして登録]
ファイルが見つからない       │      notes.md   1 KB [データとして登録]
 データ              n件    │      この5件をまとめて登録
                           │  ▸ data                    12件
                           │  ▸ data¥2026-03             4件
```

- **左はカード、右は行。** データは研究者が判断するものなのでカード、ファイルは
  フォルダの中身で300件になりうるので行です
- **フォルダごとにまとまります。** 平らな一覧は `src¥renderer¥` を全行で繰り返す
  だけで、どこに何があるかを何も言いません。深さでインデントし、自分の名前より
  前の部分は薄く出します（ファイルを持つフォルダだけが行になるので、行だけで
  組んだ入れ子には隙間ができる。パス全体が唯一の手がかりです）
- **30件を超えると畳んだ状態で開きます。** それ以下なら畳む意味がなく、超えたら
  まずフォルダの形が見たいからです。1つでも触ればその既定は外れます
- **「この◯件をまとめて登録」は開いているフォルダにだけ出ます。** 中を見ずに
  まとめて登録することにはならない、という順番です。1件ずつ登録され、失敗した
  ものは名前を挙げて報告します（成功した分は残る）

- **研究フォルダが未選択のときは、この画面は1つのことしか出しません。** 「まだ研究
  フォルダが選ばれていません」と [研究フォルダを選ぶ] だけ。2列とも空のまま描くと、
  破線の角丸が2つ並んで入力欄のように見え、まだ無いボタンの説明まで出ていました
- **左はDBのAsset、右はディスクのファイル。** 別のクラスです。Asset はファイルが
  消えても残る（そのための「ファイルが見つからないデータ」枠）
- フォルダのパスと再スキャンは**右の列だけの属性**なので、その見出しの下にあります
- 「データとして登録」は**押した時点で登録が終わります。** そのあとに「どの測定が
  生み出したデータですか」を聞きますが、答えなくても登録は済んでいます
- 片方が空なら1列（820px）になります

## ❺ 型の一覧（問い / 仮説 / 予測 / 測定）

```
仮説

なぜそうなるのか。機構や原因の主張で、それ自体は直接見えません。
「〜が左右している」だけだと、そこから出る予測は「差が出る」しか言えません。

[カード] [カード] …
```

却下したものは出ません。

**型ごとに、それが何なのかを見出しの下に書いています。** 鎖はずっと描かれて
いたのに、どこにも説明が無く、仮説と予測の違いはどの画面も一度も言っていません
でした。実際に崩れていて、8件中3件の予測が仮説の言い換えになっていました
（「Xが生着率を左右している」と「Xで生着率が分かれる」は同じ文で、後者を測っても
前者について何も分かりません）。ヘルプではなく一覧の見出しの下に置いたのは、
自分の仮説を見ている、まさにその場で照らし合わせられるからです。

## ❻ 検索（検索欄に文字が入っている間）

```
検索   「◯◯」に n件
[全型のカードを鎖の順で]
```

**却下したものへの到達経路はここだけです。** 一覧からは消え、3分後に削除されます。

## カードを開いたとき（❸❹❺❻ 共通）

```
型 / ファイルのパス
タイトル
本文
 │ 補足                      ← note列。灰色の縦線つき
[確定] [却下] / [実施した] など
┌ つながり（グレーの床）───┐
│  [上流]                  │
│  [ここ]                  │
│  [下流]                  │
│  ＋ つなぐ / はずす        │
└────────────────────┘
ローカルファイル（Assetのみ）
```

つながりの区画は**どの画面でも同じ見た目**です。マップの上では背後の図と紛れる
ので床を敷きましたが、それは部品の性質であって場所の都合ではないので、一覧でも
同じにしています。

## この文書について

**コードより先に古くなります。** 画面は `app.js` の1ファイルに収まっているので、
そちらが正です。ここは全体の形を掴むためのもので、細部が食い違ったら
`render()` と `contentHtml()` を読んでください。

更新するタイミング:

- 中央カラムに入るものが増えた・減った（`contentHtml()` の分岐が変わった）
- ナビの項目が変わった
- 設定の節が増えた・減った
- 通知の種類が増えた

ボタンの文言が変わっただけなら、ここは直さなくて構いません。
