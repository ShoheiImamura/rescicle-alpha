# ユースケースと流れ

v0.0.8 時点。画面がどこにあるかは [screens.md](screens.md)。こちらは**研究者が
何をしようとしていて、その裏で何が起きるか**です。

画面遷移が無いので、意味のある流れは画面の間ではなく**時間とやりとりの中**に
あります。以下、非自明なものだけ図にしています。

## 登場人物

| | |
|---|---|
| **研究者** | 決める人。提案を確定し、却下し、線を引き、データを登録する |
| **AI**（画面の会話） | rescicleが `claude` CLI をローカルで実行して応答。提案する人 |
| **AI**（Claude Code側） | MCP経由。同じ記録に対して同じことができる（線を外すことを除く） |
| **rescicle** | 記録を持ち、検証し、境界を守る。研究フォルダは読むだけ |

---

## UC-1 研究を始める

**きっかけ** インストールして初めて開いた

```
「いま、何を調べていますか」に書く
   │
   ├─ 1行目が研究名になる（30字で切る）
   └─ 本文がそのまま最初の発言になる
   │
[はじめる]
   │
   ├─▶ プロジェクト作成（研究フォルダは空のまま）
   └─▶ そのまま UC-2 の1往復目が走る
```

研究フォルダを聞かないので、**設定が終わる前に製品が一度動いて見えます。**
着地するのは空のマップではなく、応答が走っている画面です。

## UC-2 会話して、研究オブジェクトが現れる

**きっかけ** 研究について話す。これが主経路

```
研究者が書く ──▶ rescicle
                   │
                   ├ 会話を保存
                   ├ プロンプトを組む
                   │   ・研究オブジェクトとつながりの要約
                   │   ・ファイル名 / サイズ / 更新日時（最大120件）
                   │   ・今回の発言
                   │
                   ▼
              claude CLI を1回実行
                   │  ← 応答の文字が届くたび画面に流す
                   ▼
              { reply, operations, read_files }
                   │
                   ├ read_files が空でなければ ▶ UC-3 へ
                   │
                   ├ operations を rescicle が検証してSQLiteへ
                   │   ・1件ずつ試し、失敗しても他は通す
                   │   ・新しいオブジェクトは既定で「提案中」
                   │
                   ▼
              画面が更新される（マップ・一覧・件数）
```

**AIは記録に直接書けません。** 返ってくるのは操作の申請で、通すかどうかは
rescicle が決めます。

**現れたものは提案中です。** 確定・却下は研究者が1つずつ決めます（UC-4）。

## UC-3 AIがファイルを読む

**きっかけ** UC-2 の途中。答えがファイルの中にしかないとAIが判断したとき

```
1往復目の応答
  read_files: ["data/t2_vs_depth.csv"]
  reply: 「◯◯を読ませてください。…」   ← 一瞬画面に出る
       │
       ▼
rescicle が読む
  ・パスを研究フォルダ基準で解決 → 外に出る名前は何にも届かない
  ・テキストでなければ読まない
  ・先頭4KBまで
  ・1往復につき4ファイルまで
       │
       ▼
2往復目（同じセッション）
  中身を添えて、もう一度聞く
       │
       ▼
  reply: 実際の答え                 ← これが残り、会話に保存される
       │
       ▼
file_read として記録。ファイル画面に「読み込み済み」が付く
```

**往復は2回まで**です。1往復ごとにCLIをもう一度呼ぶので、研究者の待ち時間に
直結します。同じファイルを2度要求するループも塞いでいます。

研究者には**1つの応答に見えます。** 1往復目の返事は2往復目で上書きされます。

**先回りしては送りません。** 渡るのは名前・サイズ・更新日時だけで、中身はAIが
挙げたものだけです。1件ずつ許可を求める代わりに、**何が出ていったかを後から
見られる**ようにしています。

## UC-4 提案を決める

**きっかけ** マップや一覧に提案中（破線）のものがある

```
[確定] ──▶ マップで実線になる
             └ 通知「あと約3分は戻せます」 [戻す]
                3分を過ぎたら、決まったものとして落ち着く（常設の動詞は無い）

[却下] ──▶ 全画面から消える
             ├ 通知「あと約3分は戻せます。そのあと削除されます」 [戻す]
             └ 3分後、次にワークスペースを読んだ時点で削除
                 ・入っていた線・Asset・測定の記録も一緒に消える
                 ・events には残る（あったことと捨てたことは辿れる）

確定したものが済んだら ──▶ カードを開いて [アーカイブする]
             ・マップと一覧から外れる。検索では見つかる
             ・消えない。期限なく戻せる
```

**却下とアーカイブは別の出口です。** 却下は「間違いだった」で消えます。
アーカイブは「本物だったが済んだ」で残ります。**検証して反証された仮説は
間違いではなく研究そのもの**なので、消す先しか無いのは誤りでした。

アーカイブはカードを開いた中の控えめな位置にあります。確定・却下は1セッションに
何度も押す日常の決定で、アーカイブは稀に意図して押すものなので、並べていません。

却下したものは3分を過ぎると検索からも消えます。

AIには「却下されたものを自分から再提案するな」と指示しています。3分の猶予中は
AIからも見えているので、その間に蒸し返されません。アーカイブについては「再提案は
しないが、研究が確立したことの一部なので、関係するときは参照してよい」としています。

## UC-5 手元のファイルをデータにする

**きっかけ** 測定で出したCSVを研究の記録に入れたい

```
データ・ファイル画面
   │
   ├ 研究フォルダ未選択なら ──▶ [研究フォルダを選ぶ]
   │
   ▼
右の列から [データとして登録]
   │
   ├─▶ この時点で登録は完了       ← 押した結果がすぐ出る
   │
   ▼
通知「◯◯ をデータとして登録しました」 [開く]
   │
   └ 測定が1つでもあれば
       「どの測定が生み出したデータですか」
          │
          ├ 選ぶ ──▶ produces の線が引かれる
          │           ＋ その測定が自動で「実施済み」になる
          │           ＋ 実施日はデータファイルの更新日時を使う
          │
          └ [あとで] ──▶ 登録はそのまま残る
```

**測定を選ばなくても登録は済んでいます。** 以前は選ぶまで登録されず、押しても
何も起きないように見えていました。

## UC-6 つながりを直す

**きっかけ** AIが引かなかった線がある、または引いた線が違う

```
カードを開く
   │
   ├ [＋ つなぐ] ──▶ 相手の候補が、線が引かれる位置に並ぶ
   │                    │
   │                    └ 選んだ時点で引かれる
   │                       （型の組が述語を決めるので、選ぶのは相手だけ）
   │
   └ [はずす] ────▶ 線が消える。戻すときは引き直す
```

**画面から引けるのは鎖の4本だけ**です（仮説→問い、仮説→予測、予測→測定、
測定→データ）。残る2つ（参照する・関連する）は型を選ばないので述語を選ばせる
必要があり、いまはAI経由でしか作られません。

**AIには線を外すツールを渡していません。** AIは線を提案し、研究者が決める。
この向きは意図的に片方向です。

## UC-7 測定を実施済みにする

**きっかけ** 実際に測定した

```
[実施した] ──▶ 実施済みになる
                 └ 日付は記録しない
                    （ボタンを押した時刻は、測定がいつ走ったかを何も語らない）
```

日付が入るのは **UC-5 でデータを登録して測定につないだとき**だけです。その
ファイルの更新日時を使います。

`status`（やると決めたか）と**実施したか**は別の軸です。「確定・未実施」は
普通の状態なので、同じ軸には載せられません。

## UC-8 Claude Code側から操作する

**きっかけ** Claude Code をUIにして研究の記録を触りたい

```
設定 → [Claude Codeに追加]
   │
   ├ rescicle が claude CLI を自分で実行
   │    claude mcp remove --scope user rescicle   ← 古いパスを外す
   │    claude mcp add    --scope user rescicle -- "<exe>" --mcp-server
   │
   └ 追加されたかを読み戻して表示
        ・追加済み / まだ追加されていません / 別の場所のrescicleが追加されています
```

Claude Code に渡るツール: コンテキストの読み取り / proposedなObject・Relationの
作成 / 確定・却下 / 実施済みの切り替え / ファイル一覧 / Asset登録。

**線を外すツールはありません**（UC-6 と同じ理由）。

使う前に rescicle 側でプロジェクトを開いておく必要があります。

## UC-9 やり直す

**きっかけ** 別の研究に切り替える、またはインタビューを最初からやり直す

```
設定 → rescicleの記録 → [すべて消す] ──▶ [消す] / [やめる]
                                            │
                                            ▼
                        研究・オブジェクト・つながり・会話がすべて消える
                        Claude のセッションIDも消える
                        最初の画面に戻る
                        ─────────────────────────
                        研究フォルダのファイルには触れない
```

**2段階にしているのは、1段階目こそ誤って押されるから**です。研究フォルダに
触れないことは両方の状態に書いてあります。怖いのはそこなので。

## rescicle が守っている境界

流れのどこにいても変わらないもの。

| | |
|---|---|
| 研究フォルダ | **読むだけ。** 書き換え・作成・移動・改名・削除をしない |
| ファイルの中身 | AIが挙げたものだけ。研究フォルダの内側だけ。4KBまで |
| AIの作業場所 | 研究フォルダではなく、rescicle のエージェント用ディレクトリ |
| AIのツール | 会話ターンでは `--allowedTools WebSearch,WebFetch`。**この2つだけ** |
| AIとローカル | `Read` / `Bash` / `Edit` / `Glob` は無い。WebFetchが届くのはウェブだけ |
| 外に出る検索語・URL | AIが書く。会話と研究オブジェクトを見て書くので、研究者の言い回しが出ることがある |
| 取ってきたページ | 他人が書いた文章であって指示ではない。何を書かれていても手に入るのは「提案中」の申請だけ |
| 検索結果の扱い | 文献であって結果ではない。確定・却下の根拠にはしない（指示で縛っている） |
| AIの書き込み | 直接は書けない。操作を申請し、rescicle が検証して通す |
| 線を外す | 研究者だけ。AIにはツールを渡していない |

## 数値

| | |
|---|---|
| AIに渡すファイル名 | 120件まで |
| 1往復で読むファイル | 4件まで |
| 読み込みの往復 | 2回まで |
| 1ファイルの抜粋 | 先頭4096バイト |
| 却下の猶予 | 180秒 |
| 研究名の長さ | 1行目を30字で切る |

`src-tauri/src/commands.rs` の `READ_PER_ROUND` / `READ_ROUNDS`、
`src-tauri/src/agent.rs` の `EXCERPT_BYTES`、`src-tauri/src/db.rs` の
`REJECTED_GRACE_SECS` が正です。
